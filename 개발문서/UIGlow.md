# UI Glow 머터리얼

## 사용 방법

1. 대상 UI의 **Material**에 `Assets/Materials/UI_Glow.mat`을 할당합니다.
2. `Image`/`RawImage`는 **같은 오브젝트**에 `UIGlow` 컴포넌트를 추가합니다. 컴포넌트 메뉴는 `UI > Effects > UI Glow`입니다. **UICustomPolygonRenderer는 머터리얼만으로 자동 생성**하므로 별도 컴포넌트가 필요 없습니다.
3. 머터리얼에서 `Glow Color`, `Glow Intensity`, `Glow Radius`를 조절합니다.

기본값은 분홍색, 강도 3, 발광 밝기 3, 반경 12, 감쇠 1.2입니다. UI마다 다른 색/강도를 원하면 머터리얼을 복제해서 각각 할당합니다. 같은 머터리얼을 공유하는 UI는 설정 변경도 함께 반영됩니다.

이 방식은 카메라의 Bloom 없이 UI 메쉬 주변에 반투명한 실루엣을 여러 겹 그려서 빛 번짐을 만듭니다. 기존 Canvas/카메라/포스트 프로세싱/씬/프리팹은 변경하지 않았습니다. Screen Space Overlay에서도 사용할 수 있습니다.

원래 도형 밖으로 퍼지는 번짐에는 추가 메쉬가 필요합니다. Image/RawImage는 UIGlow가, 커스텀 폴리곤은 렌더러 자체가 공통 빌더를 통해 이 메쉬를 생성합니다. 폴리곤에 UIGlow를 직접 붙이면 그 컴포넌트의 품질 설정을 대신 사용하며 중복 생성하지 않습니다. 직접 붙인 UIGlow를 비활성화하면 자동 생성도 하지 않습니다.

## 조절 항목

- `Glow Color`: 빛 색과 알파입니다. HDR 색도 지원합니다.
- `Glow Intensity`: 0이면 번짐을 끕니다. 기본 3입니다.
- `Glow Brightness`: 발광 부분의 RGB 밝기입니다. 기본 3입니다. 원본 이미지 밝기와는 별개입니다.
- `Glow Falloff`: 부드러운 외곽 번짐의 감쇠입니다. 기본 1.2이며 낮을수록 외곽까지 빛이 유지되고 높을수록 중심에 모입니다.
- `Allow HDR Glow`: 기본 꺼짐입니다. UI 색을 SDR 범위로 제한해 씬뷰의 HDR 대상과 게임 출력 사이의 차이를 줄입니다. 실제 HDR 발광/후처리와 연동할 때만 켭니다.
- `Glow Radius`: 반경입니다. 0이면 번짐이 없습니다. 0~128 범위이며 Canvas 기준 UI 로컬 단위이므로 CanvasScaler/Transform 배율을 따릅니다.
- `Source Brightness`: 원래 이미지의 밝기를 추가합니다. 기본 0은 원래 이미지를 그대로 유지합니다.
- `Tint`: 원본 UI의 머터리얼 색/알파입니다. Glow 색은 `Glow Color`로 따로 지정합니다.
- 컴포넌트의 `Rings` / `Samples Per Ring`: 텍스처 이미지용 블러 샘플 밀도입니다. 폴리곤과 스프라이트가 없는 단색 Image는 연속 거리 계산을 사용하므로 이 수치를 높일 필요가 없습니다.

색/강도/반경은 런타임과 편집 모드에 반영됩니다. 머터리얼 인스펙터는 편집 루프를 갱신해 반경/감쇠 변경도 메쉬에 반영합니다. `Image.color` 또는 폴리곤 color의 알파와 CanvasGroup 알파를 따라 사라지며, 위치·크기·레이아웃·레이캐스트 범위는 변경하지 않습니다. 번짐만 도형 밖으로 그려지므로 주변 클릭 영역이 늘어나지 않습니다.

## 마스크와 아틀라스

Mask/RectMask2D의 **자식 UI**에 사용합니다. 스텐실 마스크, RectMask2D의 클리핑/Softness와 알파 클립 처리를 포함했습니다. 마스크 영역 바깥은 원본과 번짐 모두 잘립니다. 마스크 때문에 빛이 잘리는 경우에는 마스크 바깥에 별도의 장식용 이미지로 Glow를 배치해야 합니다.

**Mask 컴포넌트가 붙은 본체에는 번짐 메쉬를 만들지 않습니다.** 예를 들어 `transformCutinCircle` 자체가 Mask라면 그 마스크를 그대로 두고, 별도의 장식용 Image/폴리곤을 마스크와 같은 부모 아래 겹쳐 배치한 뒤 그 장식에 Glow를 적용합니다. 본체에 번짐을 추가하면 마스크 영역까지 커질 수 있어 이를 방지한 것입니다. HDR 밝기만으로 화면 전체 Bloom이 자동 생기는 방식은 아닙니다.

스프라이트 주변의 텍셀을 검색하지 않고 원본 UV를 보존한 복사 메쉬를 사용하므로 SpriteAtlas의 이웃 스프라이트 색이 번짐으로 섞이지 않습니다. 커스텀 폴리곤처럼 기본 흰색 텍스처를 쓰는 그래픽도 실루엣 번짐이 가능합니다. TextMeshPro 글자는 전용 SDF 셰이더가 필요하므로 이 머터리얼 대신 TMP의 Glow 지원 머터리얼을 사용합니다.

컴포넌트가 가까운 Canvas와 루트 Canvas의 `Additional Shader Channels > TexCoord1`을 자동으로 켭니다. 다른 UI도 사용할 수 있으므로 컴포넌트를 끌 때 이 채널을 다시 끄지는 않습니다. UV1을 자체 용도로 사용하는 다른 커스텀 메쉬 효과와는 함께 사용하지 않는 편이 안전합니다.

## 씬뷰와 게임뷰 미리보기

폴리곤의 그래픽 로컬 좌표는 UV1에 보존합니다. Canvas가 위치를 배칭/변환하더라도 씬뷰와 게임뷰에서 동일한 도형 거리와 감쇠를 계산합니다. 기본 SDR 출력은 HDR/일반 렌더 타깃에서도 같은 색을 유지합니다.

씬뷰에서만 화면 전체가 회색이거나 색감이 다르면 머터리얼 하단의 **씬뷰를 게임 UI 미리보기에 맞추기** 버튼을 누릅니다. 씬뷰의 이미지 후처리 미리보기를 끄며 게임 카메라, 씬의 Volume, 프로젝트 렌더 파이프라인은 바꾸지 않습니다. Overlay UI는 게임 카메라의 후처리 뒤에 표시되므로 씬뷰의 후처리를 켜둔 상태와는 차이가 생길 수 있습니다. 편집용 기즈모/선택 표시 역시 게임뷰에는 표시되지 않습니다.

## 성능과 검증

64개 이하 꼭짓점의 폴리곤과 스프라이트가 없는 단색 Image는 **확장된 사각형 1장(정점 4개)**에서 실제 외곽선까지의 거리를 계산합니다. 단계별 실루엣을 겹치지 않으므로 띠가 생기지 않으며, 바깥 경계에서 알파와 기울기가 함께 0으로 줄어듭니다. 오목한 단순 폴리곤도 같은 거리/내외 판정을 사용합니다. 도형별 좌표를 전달하는 숨겨진 렌더용 머터리얼을 오브젝트당 하나 재사용하고 비활성화/파괴 시 정리합니다. 원본 공유 머터리얼의 값은 수정하지 않습니다.

텍스처 Image/RawImage 및 매우 복잡한 폴리곤은 기존 메쉬 블러 경로를 사용하되, 고정된 동심원 대신 저불일치 디스크 샘플을 분산해 층이 보이는 현상을 줄였습니다. 해당 경로의 기본 품질은 원본을 포함해 65개 실루엣입니다. 넓은 화면 전체 이미지나 많은 항목에는 품질을 낮추는 것이 좋습니다. UI 정점 수 제한에 맞춰 샘플 수를 자동 제한하며 실제 게임 효과에서 Bloom/RenderTexture를 추가 생성하지 않습니다.

`UIGlowTests`는 머터리얼/셰이더 연결, UV·색/알파 보존, 원본 메쉬 순서, 무효/비활성 상태, Canvas 채널 유지, 마스크 재질 동기화와 스텐실 상태 보존을 확인합니다. `UIGlowRenderTests`는 실제 CanvasRenderer까지의 폴리곤 자동 메쉬 경로, 중복 방지 및 카메라 픽셀 리드백으로 기본값의 Image/폴리곤 가시성과 마스크 안팎을 검사하도록 작성했습니다. GPU 리드백 테스트는 그래픽 장치가 있는 별도 Built-in 렌더 파이프라인 테스트 프로젝트에서 실행해야 하며, 기존 URP 프로젝트에서는 해당 GPU 항목을 건너뜁니다.

C# 빌드와 실제 설치된 Unity CGIncludes를 사용한 D3D HLSL 컴파일(정점 단계와 색 공간/RectMask/AlphaClip 조합 8개 픽셀 단계)을 통과했습니다. 이후 사용자 승인으로 별도 테스트 프로젝트에서 Unity 6000.0.32f1 / Direct3D 11 / RTX 4070 Ti의 실제 GPU 렌더링 검증을 실행했습니다. **12개 테스트 모두 통과했고 실패/건너뜀은 0개**입니다. Image·폴리곤의 기본값 가시성, 삼각형 꼭짓점 이동, Mask/RectMask2D 안팎 클리핑을 픽셀 리드백으로 확인했습니다.

최신 검증에서는 본 프로젝트와 같은 **Linear** 색 공간에서 **17개 테스트 모두 통과**했습니다. 실제 경계 픽셀의 단조롭고 부드러운 감쇠, HDR/LDR 출력 일치, 같은 조건의 Game/SceneView 카메라 유형 일치, 이동/회전/배율과 Canvas 배칭, 도형이 0 크기에서 펼쳐질 때의 재질 연결까지 검사했습니다. 별도 Built-in 테스트 프로젝트이며 작업 중인 URP 로비 씬을 직접 재생한 것은 아닙니다. 작업 씬과 열려 있는 편집기는 변경/재시작하지 않았습니다. 최신 [부드러운 Glow 검증 결과](검증결과/UIGlow-Smooth/검증결과.md)와 이전 [검증 결과](검증결과/UIGlow/검증결과.md)를 따로 보존했습니다.

관련 Unity 자료: [Canvas 추가 셰이더 채널](https://github.com/Unity-Technologies/UnityCsReference/blob/master/Modules/UI/ScriptBindings/UICanvas.bindings.cs), [uGUI Mask의 스텐실 동작](https://github.com/Unity-Technologies/uGUI/blob/main/com.unity.ugui/Documentation~/script-Mask.md). 구현은 프로젝트에 설치된 Unity 6000.0.32f1/UGUI 2.0.0의 코드와 CGIncludes를 기준으로 작성했습니다.
